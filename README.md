# Capture All — многопользовательская игра по захвату территории

Браузерная онлайн-игра в духе paper.io. Игроки собираются в комнате, каждый управляет своей «головой» на общем поле, выходит за пределы своей территории, рисует след и, вернувшись домой, захватывает всё, что оказалось внутри замкнутого контура. Побеждает тот, у кого к концу раунда больше всего территории.

Приложение — это один Node.js-процесс: он отдаёт страницы по HTTP, общается с клиентами по WebSocket и (опционально) сохраняет комнаты и таблицу побед в PostgreSQL.

## Возможности

- Комнаты на 2–10 игроков с уникальной ссылкой.
- Настраиваемый размер поля: от 20×20 до 150×150 клеток.
- Свой ник у каждого игрока.
- Таблица побед в каждой комнате, которая переживает перезапуск сервера (при подключённой базе).
- Защита от подмены ников: победы привязаны к токену браузера, а не к нику.
- Автоматическое переподключение клиента при потере связи.
- Управление только стрелками на клавиатуре.

## Правила игры

- Поле — квадрат из клеток. Каждый игрок стартует в зоне 3×3 своего цвета и движется непрерывно в одном направлении.
- Направление меняется стрелками. Развернуться на 180° нельзя.
- Пока игрок находится на своей территории, он ничего не рисует. Выйдя за её пределы, он оставляет **след**.
- Когда игрок возвращается на свою территорию, след превращается в территорию, а все клетки, замкнутые контуром, тоже становятся его собственными.
- **Игрок погибает**, если:
  - задел собственный след;
  - вышел за границу поля;
  - его след задел другой игрок;
  - чужой контур замкнулся поверх его следа;
  - столкнулся лоб в лоб с другим игроком: идут в одну клетку или меняются клетками, тогда гибнут оба;
  - у него не осталось ни одной своей клетки.
- Погибший игрок теряет всю территорию, но остаётся в комнате как наблюдатель до конца раунда.
- **Конец раунда:** через 90 секунд или когда в живых остаётся не больше одного игрока.
- **Победитель** — игрок с наибольшим процентом захваченной территории. При равенстве победа засчитывается всем лидерам, если их результат больше нуля.
- После раунда все возвращаются в лобби, и хост может запустить новый.

## Комнаты и лобби

1. На главной странице выбирается число игроков и размер поля, после чего создаётся комната и происходит редирект на `/room/<id>`.
2. Перед входом игрок вводит ник. Ник сохраняется в `localStorage`.
3. Игра стартует **автоматически**, когда комната заполнена. Хост (первый вошедший) может нажать «Начать игру» раньше, если собралось минимум 2 игрока.
4. В уже идущую игру новых игроков не пускают.
5. Пустая комната хранится час после последней активности, затем удаляется вместе с таблицей побед.

## Архитектура

```
Браузер  ──HTTP──►  server.js  ──►  public/*.html
   │                    │
   └─────WebSocket──────┤  ──►  game.js   (логика игры)
                        └────►  db.js     (PostgreSQL, опционально)
```

| Файл | Назначение |
| --- | --- |
| `server.js` | HTTP-сервер, WebSocket, комнаты, игровой цикл, учёт побед, обработка ошибок |
| `game.js` | Чистая игровая логика: поле, движение, следы, захват, столкновения |
| `db.js` | Работа с PostgreSQL: схема, загрузка и сохранение комнат и побед |
| `public/index.html` | Страница создания комнаты |
| `public/room.html` | Клиент игры: ник, canvas, список игроков, таблица побед |
| `render.yaml` | Описание деплоя на Render (веб-сервис и база данных) |

### HTTP-маршруты

| Маршрут | Что делает |
| --- | --- |
| `GET /` | Страница создания комнаты |
| `GET /create?n=<игроков>&size=<размер>` | Создаёт комнату и перенаправляет на `/room/<id>`. `n` ограничивается 2–10, `size` — 20–150 |
| `GET /room/<id>` | Страница игры (`id` — 8 hex-символов) |
| `GET /health` | Проверка состояния, возвращает `ok` |
| `WS /ws?room=<id>&nick=<ник>&token=<токен>` | Игровое соединение |

### Игровой цикл

Каждая комната, пока идёт игра, имеет свой таймер с тиком раз в 120 мс. За тик сервер:

1. Применяет накопленные направления игроков.
2. Находит лобовые столкновения и убивает участников.
3. Двигает остальных: проверяет границы, чужие и собственные следы, рисует след или замыкает контур и захватывает территорию.
4. Убивает игроков, у которых не осталось территории.
5. Рассылает всем клиентам полное состояние поля.
6. Проверяет условия конца раунда.

**Захват территории.** Когда контур замкнулся, алгоритм заливкой от границ поля находит все клетки, до которых нельзя добраться, не пересекая территорию игрока. Эти клетки и становятся его территорией.

**Направления.** Сервер принимает направление только если оно не противоположно тому, в котором игрок реально двигался на предыдущем шаге. Поэтому быстрая последовательность клавиш не приводит к развороту в собственный след.

### Протокол WebSocket

Все сообщения — JSON.

**Клиент → сервер**

| Сообщение | Значение |
| --- | --- |
| `{"type":"start"}` | Запустить игру. Работает только у хоста |
| `{"type":"dir","dx":1,"dy":0}` | Сменить направление |

**Сервер → клиент**

| `type` | Содержимое |
| --- | --- |
| `name` | Ник игрока после проверки на уникальность |
| `lobby` | Список игроков, хост, лимиты и таблица побед комнаты |
| `start` | Размер поля, список игроков с их id, длительность раунда (`duration`) и оставшееся время (`remaining`) |
| `you` | Ваш id в игре |
| `state` | Поле (`owner`, `trail` — строки, по символу на клетку), игроки с позициями и очками, оставшееся время, события гибели `events` (`victim`, `killer`, `reason`) |
| `end` | Итоги раунда: имена, цвета, проценты |
| `aborted` | Раунд прерван из-за внутренней ошибки сервера |

**Коды закрытия соединения**

| Код | Причина | Клиент переподключается? |
| --- | --- | --- |
| 4004 | Комната не найдена | нет |
| 4005 | Игра уже идёт | нет |
| 4006 | Комната заполнена | нет |
| 4007 | Комната открыта в другой вкладке | нет |
| 4008 | Неверный токен | нет |
| остальные | Потеря связи | да, через 2 секунды |

## Ники, токены и победы

- Браузер при первом заходе генерирует случайный токен (32 байта) и хранит его в `localStorage`. Сервер хранит и сравнивает только его SHA-256.
- Победы считаются **по токену**, а не по нику. Ник — только отображаемое имя.
- Если вы выбираете ник, уже занятый другим игроком в комнате или закреплённый за ним в таблице побед, сервер добавляет суффикс: `Вася (2)`, `Вася (3)` и так далее.
- Повторное подключение с тем же токеном вытесняет прежнее соединение: закрывается старая вкладка, а новая занимает то же место. Один человек не может играть сам против себя двумя вкладками.
- Режим инкогнито или очистка `localStorage` дают новый токен, то есть нового игрока. Это ограничение схемы без аккаунтов.

## Хранение данных

С PostgreSQL (если задана переменная `DATABASE_URL`):

- таблица `rooms` — id, число игроков, размер поля, время последней активности;
- таблица `player_wins` — победы по паре «комната + хэш токена» и последний ник.

При старте сервер создаёт таблицы, загружает комнаты в память и продолжает работать с ними. Идущая игра в базу не сохраняется: после перезапуска раунд прерывается, а клиенты автоматически возвращаются в лобби той же комнаты.

Без `DATABASE_URL` всё хранится в памяти процесса и пропадает при перезапуске. Если `DATABASE_URL` задан, но база недоступна, сервер завершается с ошибкой.

> При старте выполняется `DROP TABLE IF EXISTS wins`: это старая таблица, где победы были привязаны к нику. Её данные в новую схему перенести нельзя.

## Запуск локально

Требуется Node.js 18 или новее.

```bash
npm install
npm start
```

Игра будет доступна на http://localhost:3000. Чтобы проверить игру на нескольких игроках, откройте ссылку комнаты в нескольких профилях браузера (вкладки одного профиля вытесняют друг друга).

### Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `PORT` | Порт HTTP-сервера | `3000` |
| `DATABASE_URL` | Строка подключения к PostgreSQL | не задана, работа в памяти |
| `DATABASE_SSL` | `true` — подключаться к базе по SSL (сертификат не проверяется) | выключено |

## Деплой на Render

Конфигурация лежит в `render.yaml` и создаёт сразу два ресурса:

- веб-сервис `capture-all` (Node.js, бесплатный план, проверка состояния `/health`);
- базу данных PostgreSQL `capture-all-db`, строка подключения которой автоматически передаётся сервису как `DATABASE_URL`.

Порядок действий:

1. Запушить проект в Git-репозиторий.
2. В Render выбрать New → Blueprint и указать репозиторий.
3. После создания сервиса адрес вида `https://<имя>.onrender.com` и будет публичным адресом игры.

Ограничения бесплатного плана Render:

- сервис засыпает после простоя, первое подключение может занять около 30 секунд;
- бесплатная база данных удаляется через 30 дней после создания, если не перейти на платный план;
- файловая система сбрасывается при каждом деплое, поэтому SQLite для хранения не подойдёт.

## Устойчивость и безопасность

- Размер входящего WebSocket-сообщения ограничен 1 КБ. Слишком большое сообщение закрывает только это соединение.
- На каждом сокете и серверах есть обработчики `error`, а глобальные `uncaughtException` и `unhandledRejection` пишут ошибку в лог и не дают процессу упасть.
- Ошибка в игровом тике прерывает раунд только в одной комнате.
- Живость соединений проверяется ping/pong раз в 30 секунд, мёртвые клиенты отключаются.
- Все SQL-запросы параметризованные.
- Ники отображаются через `textContent`, поэтому HTML в нике не выполняется.
- Имена статических файлов зашиты в коде, обход путей невозможен.

## Известные ограничения

- Сервер каждый тик отправляет полное состояние поля. На больших полях (150×150) и при 10 игроках это заметный трафик. Следующий шаг оптимизации — отправка только изменений.
- Нет ограничений на число создаваемых комнат и соединений с одного адреса, и нет проверки заголовка `Origin` у WebSocket.
- Идентификатор комнаты — 8 hex-символов (32 бита), его теоретически можно перебрать.
- `GET /create` меняет состояние, его правильнее сделать POST-запросом.
- Нет заголовков безопасности (Content-Security-Policy и других).
- Игрок, потерявший соединение во время игры, считается погибшим. Вернуться в раунд можно только если старое соединение ещё не закрыто, например при открытии второй вкладки.
- Управление только клавиатурой, на телефоне играть нельзя, а смотреть можно.
- При подключении с `DATABASE_SSL=true` сертификат базы не проверяется.
